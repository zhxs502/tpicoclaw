# 切模型无效（UI 切了仍由 deepseek 回答）— 2026-11-12

config：/data/user/0/com.sipeed.picoclaw/files/picoclaw/config.json

## 现象
Web/App 聊天页模型下拉切到别的模型，回答仍是 deepseek。R 手动重启 gateway 也一样。

## 根因（代码级）
模型解析有三级优先级，UI 只改第三级。

pkg/agent/instance.go:648 resolveAgentModel()
  1. AGENT.md frontmatter 的 model:      ← 我的 AGENT.md 没有
  2. agents.list[].model.primary         ← config 里 main 写的是字符串 "deepseek"
  3. agents.defaults.model_name          ← UI 改的只有这个

前端链路：
  web/frontend/src/hooks/use-chat-models.ts:70  handleSetDefault → api/models.ts:133 setDefaultModel
  → POST /api/models/default
  → web/backend/api/models.go:1030 handleSetDefaultModel
     只执行 cfg.Agents.Defaults.ModelName = modelName（+ 清 fallback），
     完全不动 agents.list。注释写的是 "sets the default model for all agents"，与实现不符。

所以 main agent 被第 2 级钉死在 deepseek，第 3 级怎么改都轮不到。

## 顺带确认（不是原因）
- pkg/config/workspace_isolation.go:38 api_key_fingerprints 已标 deprecated，运行时忽略。
- pkg/agent/instance.go resolveWorkspaceAgent 建 workspace 变体时 Model: {Primary: base.Model}，
  即变体继承 base 的 model → 切工作区也不会换模型。
- AgentModelConfig 有自定义 UnmarshalJSON（pkg/config/config.go:284），支持 "model": "字符串" 简写，
  所以 config 里那种写法是合法的，不是配置写坏。

## 生效机制（代码证据）
pkg/gateway/gateway.go:587 handleConfigReload
  → createStartupProvider(newCfg)
  → al.ReloadProviderAndConfig（pkg/agent/agent.go:381）
      → pkg/agent/agent.go:404 NewAgentRegistry(cfg, provider) 全量重建 agent 实例
  → restartServices
即 config 改动会被 watcher 抓走，agent 实例重建，不需要杀进程。

坑预警：gateway.go 里 reload 后有
  if newModelID != "" { newCfg.Agents.Defaults.ModelName = newModelID }
会把 alias 覆盖成 provider 返回的真实 model id（例如 alias "deepseek" → "deepseek-chat"）。
所以 reload 之后 redisplays 的 default model 可能跟 UI 上选的名字不一样，属正常，别当成没生效。

## 源码修改（方案 B，2026-11-12 落地，待主力机编译验证）
文件：web/backend/api/models.go

1) handleSetDefaultModel 里，改 defaults 之前先抓旧值：
     oldDefault := strings.TrimSpace(cfg.Agents.Defaults.ModelName)
     cfg.Agents.Defaults.ModelName = modelName
     cfg.Agents.Defaults.ModelFallbacks = removeModelName(...)
     repointPinnedDefaultAgents(cfg, oldDefault, modelName)   // 新增
     normalizeDefaultChainReferences(cfg)
   函数注释同步改成"重指跟随全局默认的 agent，钉了别的模型的不动"。

2) 新增两个函数（放在 handleSetDefaultModel 上方）：
   repointPinnedDefaultAgents(cfg, oldDefault, newDefault)
     - 遍历 cfg.Agents.List，对每个 agent 的 Model 和 Subagents.Model：
       若该 pin 是"跟随旧默认"（见下），Primary 改成 newDefault，
       并从它的 Fallbacks 里去掉 newDefault。
     - Model == nil / Primary == "" 的原样不动（本来就继承 defaults）。
   followsGlobalDefault(model, oldDefault, modelList) bool
     - pin trim 后 == oldDefault → true
     - 否则在 modelList 里找 ModelName == oldDefault 的那条，
       若 pin == 那条的 Model（真实 model id）→ true
     - 目的：热 reload 后 defaults.model_name 可能被改写成真实 id
       （见上文"坑预警"），此时 pin 里还是 alias，两种情况都算跟随。

3) 测试：web/backend/api/models_test.go 新增两个
   TestHandleSetDefaultModel_RepointsAgentsFollowingDefault
     main(pin=old default) → 跟随; kimi(pin=claude) → 不动;
     inherit(model=nil) → 仍为 nil; sub.Subagents.Model 同样跟随。
   TestHandleSetDefaultModel_RepointsAgentPinnedToConcreteModelID
     defaults=alias、pin=concrete id 的别名错位场景。

没改前端：UI 仍只有一个"默认模型"下拉，靠后端重指生效。
若以后要区分"全局默认 / agent 独立绑定"，得改 UI（需一起重编前端产物）。
